# 媒体优化验收 Checklist（固定流程）

适用范围：本仓库的**图片/视频加载优化**（响应式 `<picture>`、长图分批加载、视频延迟加载、GitHub Pages 构建期生成多格式多尺寸资源）。

## 验收原则（必须满足）
- **布局不变**：视觉结构、比例、间距保持与优化前一致；允许“更快显示/更少白屏”，不允许“版式变形/抖动”。
- **可用性优先**：任何新能力都必须有**可控回退**（不支持 AVIF/WebP、变体文件缺失、脚本异常时仍能看到原图/使用页面）。
- **生产/测试一致**：`dev`、`preview`、线上（GitHub Pages）行为一致；至少保证功能一致，允许性能略有差异。

## 一、验收环境准备（必做）
- **本地预览**：运行 `npm run build && npm run preview`
- **dev 验证**：运行 `npm run dev`（用于快速回归交互，但性能以 `preview/线上` 为准）
- **浏览器矩阵**
  - 桌面：Chrome（必测）、Safari（建议）
  - 移动：iOS Safari（必测）、Android Chrome（建议）
- **网络档位（DevTools）**
  - 移动口径：Fast 3G 或 Slow 4G（二选一固定）
  - CPU：4x（用于观察解码/主线程卡顿）

## 二、布局回归（视觉/CLS）
目标：**优化后布局与优化前一致**，且 CLS 不上升。

### 首页（`/`）
- **轮播容器**：仍为 16:9；左右箭头与 dots 位置不偏移
- **首屏产品区**：卡片比例、拼图网格、hover 行为一致

### 产品详情（`/products/{productId}`）
- **主图区域**：仍为 1:1；缩略图排列不异常（不溢出/不莫名换行）
- **长图区域**：滚动过程中不出现“突然上推/下拉跳动”

### 硬性阈值
- **CLS**：Lighthouse Mobile 目标 ≤ 0.1（理想 ≤ 0.05）

## 三、功能正确性（回退策略）
### 1）AVIF/WebP 回退（浏览器兼容）
- Safari / iOS Safari：确保图片正常显示（即使不支持某些格式，也会使用 `<img src="/images/...">` 兜底）

### 2）变体资源缺失回退（容错）
手动模拟变体缺失，页面仍必须可用：
- 打开 DevTools → Network → Request blocking
- 增加阻断规则：`*/images-gen/*`
- 刷新页面
- 期望：图片仍可显示（回退到原始 `/images/...`），页面不白屏；允许控制台出现非致命告警，但不允许报错导致渲染中断

### 3）视频不偷跑下载
在产品详情页：
- 初次进入页面时 **Network 不应出现视频文件请求**
- 点击“视频”tab 后才出现视频请求，并能播放
- 切回“图集”后视频会暂停

## 四、性能验收（Network + Lighthouse）
说明：Lighthouse 分数只是参考，**以实际 Network 字节数与关键行为为准**。

### 1）首页首屏（LCP）
在 Lighthouse Mobile（或等效流程）下：
- **LCP**：目标 ≤ 2.5s（移动档）
- **TBT**：目标 ≤ 200ms

Network 观察点（只统计 LCP 前后关键窗口）：
- 首屏图片总字节明显下降（目标：≥ 30%；理想 ≥ 50%）
- 非首屏图片不会在首屏阶段“抢带宽”（lazy 生效）

### 2）产品列表（首页 products 区）
- 首屏 1~2 个卡片图片能尽快显示，其余滚动到可视区域再加载
- 列表滚动时不卡顿（解码不造成长任务堆积）

### 3）产品详情页（图集 + 长图）
图集：
- 点击缩略图切换主图不应明显延迟
- 切换规格导致图集刷新时仍能正常加载

长图（重点）：
- 初次进入页面时，Network 不应把全部长图排队请求
- 快速滚动到底部：长图逐步加载，不应出现长时间大片空白
- 快速反复滚动：页面不应明显掉帧/卡死

## 五、线上缓存验证（GitHub Pages）
目标：回访加载明显变快。
- 线上打开一次（冷启动）后，再次普通刷新（非 hard reload）
- DevTools → Network：图片变体应大量命中 `disk cache / memory cache`

## 六、验收输出物（每次改动必须提交/归档）
建议在 PR/发布记录中附上：
- 首页、详情页各一张 **Network 截图**（含 throttling 档位）
- Lighthouse Mobile 关键指标（LCP/CLS/TBT）
- “视频不偷跑”验证截图（或 HAR 片段）
